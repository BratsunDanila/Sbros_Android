# Облачная синхронизация

Аккаунт Supabase необязателен: без настройки приложение работает с локальными записями.

Для собственного облачного проекта:

1. Создай проект Supabase и настрой вход по электронной почте и паролю.
2. В пустой базе выполни SQL из `migrations/` по порядку: 001, 002, 003, 004, 005, 006. Уже применённые миграции, особенно 003, повторять не нужно.
3. Добавь URL проекта и публичный publishable/anon-ключ в свой `local.properties` по примеру в корне репозитория. Административный `service_role` в приложение не передаётся.
4. Собери приложение, войди в аккаунт и подтверди перенос локальных записей, если он нужен.

Записи разделены на `captures`, `projects`, `tasks`, `thoughts`, `events`, `materials` и `analysis_runs`. Профиль хранится в `profiles`. Доступ к данным ограничен пользователем через RLS.

Обмен использует `sync_push_v3`, `sync_pull_v3`, атомарное подтверждение `sync_confirm_capture_v1` и проверку версии `sync_schema_version`. Room остаётся локальным источником записей. Миграции 005 и 006 нужны для согласованного подтверждения разбора и сохранения состояния проектов.

Личный ключ Token Harbor хранится только на устройстве и не передаётся в Supabase.
