# PRODUCT & UX SPEC — СБРОС Android MVP

## 0. Продуктовая идея
Один простой вход («Сброс») и несколько красивых мест для результата. Пользователь не обязан изучать GTD, назначать категории и разбирать каждую мысль сразу. Внешне — очень спокойное и премиальное приложение, в ядре — надёжная система управления личными обязательствами.

Пятиэкранная нижняя навигация: `Дела | Мысли | Сброс | Календарь | Обзор`.
Экран «Сброс» — главная точка входа и начальная вкладка после входа, если не было явного выбора. Центральная кнопка заметна, но не выпирает над панелью; одинаковая базовая линия с остальными кнопками.

## 1. Приветствие / регистрация / вход (НОВОЕ)
- Splash/restore session с приятным минималистичным состоянием.
- Welcome: знак/название «Сброс», лаконичный смысл «Освободи голову. Остальное разложим вместе», кнопки `Начать` / `У меня уже есть аккаунт`.
- Регистрация по email + пароль (валидация, показать/скрыть пароль, обработка ошибок, confirmation email — согласно настройкам Supabase Auth).
- Вход, выход из аккаунта, восстановление доступа к аккаунту; состояние разлогина при истёкшей сессии.
- Обязательное отсутствие захардкоженного имени «Данила»; имя опционально из профиля.
- Экран настроек: тема светлая/тёмная, палитры lavender/sage/clay/ocean, аккаунт, выход, приватность/удаление информации.
- Любые незаполненные внешние ключи должны приводить к явной ошибке настройки, не к фиктивному «успеху».

## 2. Сброс — главная ценность
### 2.1 Пустой экран ввода
Крупный вопрос «Что у тебя на уме?», несколько строк спокойного пояснения, большой центрированный микрофон с мягкими окружностями/пульсацией, поле текста, `На потом` и `Разобрать`.
Говорить ИЛИ печатать; текст можно исправить даже после транскрибации. Учитывать разрешение RECORD_AUDIO, отсутствие службы, таймаут и отмену записи. Пульсация только во время активного слушания. Зафиксировать распознанный текст, не потерять partial/final transcript при повторном старте.

### 2.2 Сохранить «На потом»
Создать исходную запись `capture` со статусом `inbox`. Не просить категорию, не запускать ИИ. Позволить потом открыть входящие через «Обзор» и продолжить разбор.

### 2.3 Разобрать
1) Сначала надёжно сохранить исходную запись; 2) отправить её на авторизованную Edge Function; 3) показать состояние обработки; 4) получить список редактируемых **предложений**, не готовых дел; 5) вывести карточки.

В случае таймаута или ошибок сети исходная запись остаётся во входящих. Есть `Повторить` и `Вернуться к записи`. Никакого молчаливого перехода на симуляцию.

### 2.4 Подтверждение
Карточка предложения имеет: тип/категорию, название (можно менять), удалить/вернуть, дату и время для календарного события. Можно добавить новую карточку или сменить тип; поддержать 9 маршрутов, перечисленных ниже. Отдельно доступна исходная запись без потери текста.
- `next` — дело, следующее действие.
- `reflection` — личное размышление/дневник.
- `idea` — идея.
- `waiting` — ожидание ответа/действия от другого человека.
- `projects` — проект как желаемый результат.
- `cal` — событие с подтверждённой конкретной датой.
- `someday` — когда-нибудь/может быть.
- `notes` — справочный материал.
- `inbox` — оставить фрагмент неразобранным.

`Подтвердить` выполняет **одну транзакцию** записи принятых карточек, привязывает их к исходному capture и отмечает capture подтверждённым. Не создавать дубликаты при повторном нажатии или восстановлении после обрыва сети. До подтверждения ИИ-предложения не являются пользовательскими планами.

### 2.5 После подтверждения
Короткое приятное состояние успеха с количеством созданных элементов; понятный переход к вкладкам, плюс `Ещё один сброс`.

## 3. Дела
- Большой заголовок «Дела.» без лишних верхних надписей.
- Выбор уровня «Просто / Средне / Сложно».
- Визуально выразительная карточка на стопке: сфера, название конкретного действия, необязательная подсказка, `Другое`, `Готово` и свайпы с обратной связью.
- `Другое` не меняет статус задачи, только показывает следующую. `Готово` сохраняет completed_at и статус done.
- Нет задач => спокойное пустое состояние без упрёков.
- Помощь «Нужен маленький первый шаг?» может обращаться к Token Harbor отдельной функцией/операцией и не изменяет задачу без подтверждения.
- Сохранять контекст проекта, если действие входит в проект. Обеспечить просмотр полного списка действий через «Обзор».

## 4. Мысли
- Полноценная равноправная вкладка, не вложение в «Обзор».
- Характерная композиция из v14: большой заголовок «Мысли.», нежный блок «Здесь не нужно ничего успевать», лента.
- Фильтры `Все / Идеи / Дневник / Любимое`, поиск, карточка с датой, заголовком и фрагментом текста.
- Открытие подробностей, редактирование, продолжение мысли, избранное, удаление с подтверждением/undo по возможности, создание действия из мысли **не удаляя исходную мысль**.
- Поиск по тексту для MVP. Семантические связи между мыслями — опционально позднее, после настоящих embeddings/RAG, без фальшивого «умного поиска».
- Не диагностировать эмоции и не превращать переживания в задачи.

## 5. Календарь
- Заголовок «Календарь.», мягкий декоративный блок, месяц, выбор дня, события выбранного дня, добавить/редактировать/удалить событие.
- Не ставить туда любую задачу автоматически; только событие с действительно указанной/подтверждённой датой. Если ИИ не знает дату — не придумывает её.
- Поддержка времени и события на весь день.

## 6. Обзор
- Заголовок «Обзор.», крупная карточка «Входящие», плитки `Проекты / Ожидаю / Когда-нибудь / Материалы`, тихие строки `Все действия / Сделано`, недельный обзор, история сбросов.
- Во входящих есть исходные записи на потом: открыть/разобрать/удалить.
- Проекты как самостоятельные желаемые результаты; у проекта может быть несколько задач и конкретное следующее действие. Не путать «подшаги» и GTD-проекты.
- Недельный обзор: входящие, наличие следующих действий у проектов, ожидания, идеи на будущее; сохранение даты последнего обзора, без принудительных streak.
- История показывает **оригинальную запись**, даже если после неё было создано много объектов; связь сохраняется.

## 7. Нефункциональные требования
- Русский язык — интерфейс и основной разбор; подготовить строки к локализации.
- Обработка network errors, пустых списков, коротких и очень длинных записей, длинных заголовков, поворота экрана, большой системный шрифт.
- Тон: спокойный, без давления и оценки продуктивности.
- Правильные семантика, контраст и touch targets; уважать `reduce motion`/Android animator duration scale.
- Не сохранять сырой аудиопоток по умолчанию. Явное пользовательское управление удалением исходного текста и связанных объектов.
- Проверять на ширинах 320, 360, 390 dp и разных системных навигационных панелях.

## 8. Ключевые тестовые сценарии
A. Пустое приложение → Welcome → регистрация → подтверждение email (если включено) → вход → «Сброс».
B. Голос → частичная/финальная расшифровка → редактирование → «На потом» → «Входящие» → разбор.
C. Смешанный текст: «Надо купить корм. Устал после учёбы. Придумал приложение для языков. Жду ответа преподавателя» → 4 предложения `next`, `reflection`, `idea`, `waiting`; пользователь исправляет предложение и подтверждает → записи появляются в правильных местах, исходник остаётся.
D. Пользователь отменяет разбор/нет сети → исходная запись во входящих, без созданных задач.
E. Неуказанная дата не превращается в календарное событие с выдуманным временем.
F. `Другое` не меняет статус задачи; `Готово` меняет; после relaunch состояние сохранено.
G. Пользователь A не может прочесть/изменить записи пользователя B через Supabase API.
H. На 320 dp навигация из 5 элементов и центральный микрофон остаются читаемыми, не перекрывают контент.
