# Обновление «Сброса» до v15

Изменён существующий Android-проект. Главный эталон этого обновления — `reference/sbros_v15_full_list.html`; его отличие от v14 проверено по CSS и JavaScript. Исправление статических начертаний Onest сохранено.

## Изменения

- `feature/TasksScreen.kt`: один `LazyColumn` для заголовка, рекомендуемого дела и полного списка остальных `next`. Фильтры сложности удалены. Карточка 253 dp / компактная 222 dp (может расти при длинном тексте), подпись «ПРЕДЛАГАЮ СЕЙЧАС», счётчик, помощь первого шага и строки 59/52 dp оформлены по v15. Выбор строки возвращает к карточке; чекбокс завершает только выбранное дело. Нижняя панель находится за пределами списка и остаётся неподвижной. Стабильные ключи и `animateItem` сохраняют плавность перестановок.
- `data/TaskActions.kt`, `data/DemoState.kt`: выбранное дело хранится по ID, не по позиции/сложности. Завершённые/ожидающие/«когда-нибудь» исключены. При удалении/смене статуса выбранного дела фокус согласуется с актуальным списком. Повторное завершение уже выполненного дела ничего не меняет. Адресная отмена по токену возвращает только конкретный статус и не откатывает другие дела, тексты и входящие. Фокус, журнал отмены и опциональный исходник мысли сериализуются в SavedStateHandle с совместимостью старых данных.
- `feature/ThoughtsScreen.kt`: удалена закреплённая кнопка «Новая мысль» вместе с её обработчиком и зарезервированным нижним пространством. Лента, поиск, фильтры и детали сохранены.
- `feature/Sheets.kt`: если у мысли есть `sourceText`, показывается «Посмотреть исходный сброс». У фикстур без оригинала эта ссылка отсутствует. Редактирование/продолжение мысли сохраняют оригинал.
- `core/designsystem/Components.kt`, `feature/CalendarScreen.kt`, `feature/OverviewScreen.kt`: общий верхний отступ 18 dp внутри уже учтённого status bar, общий компонент Heading, интервал 20/15 dp. Заголовки соответствуют v15: 43 sp; на узком экране 40 sp, календарь 36 sp. Центрированная композиция «Сброса» не менялась.
- `SbrosApp.kt`: подключены действия ViewModel, адресная отмена и просмотр исходника. Новое уведомление заменяет предыдущее, поэтому быстрые завершения не накапливают устаревшие кнопки отмены.
- `res/values/strings.xml`, `feature/Previews.kt`, `README.md`, `app/build.gradle.kts`: актуальные тексты/превью и версия `0.2.0-demo-v15` (code 3).

## Проверка

Команда сборки и статических проверок:

```powershell
$env:JAVA_HOME='D:/andriodstudio/jbr'
./gradlew.bat assembleDebug assembleDebugAndroidTest testDebugUnitTest lintDebug
```

- `TaskActionsTest`: 6 unit-тестов — 0/1/50 доступных дел, категории сложности без фильтрации, отсутствие дублей, выбор, завершение 50 дел подряд, адресная отмена, защита от повторов и устаревшей отмены, сохранение последующих правок/входящих.
- `TaskListUiTest`: реальная прокрутка до 50-го дела, выбор и возврат в карточку, независимый чекбокс, свайпы, обновление/добавление, пустой/единственный элемент, условный просмотр исходника.
- `DemoStatePersistenceTest`: новый экземпляр ViewModel из сохранённых значений восстанавливает фокус, отмену и полный исходник мысли.
- `VisualSmokeTest`: все вкладки, одинаковая верхняя координата четырёх заголовков, неподвижность навигации при прокрутке, отсутствие старых фильтров/кнопки создания мысли, пересоздание Activity с выбранным делом и черновиком, темы и поиск.
- `FontRenderingTest`: реальное различие статических весов Onest через загрузчик Compose.

Проверка выполняется на отдельном AOSP Android 15 x86_64 эмуляторе, 160 dpi. Постоянные пользовательские виртуальные устройства не менялись. При подготовке обнаружены блокировка общего кеша Gradle и сбой SwiftShader; кеш освобождён штатной остановкой демонов, эмулятор запущен с ANGLE без Vulkan. Эти операции не изменили библиотеки или настройки приложения.

## Сопоставление с HTML и ограничения

Сопоставлены финальные CSS-переопределения v15: размеры/отступы заголовков, 253/222 dp карточки, подписи и счётчики, поля карточки, интервалы списка, отсутствие фильтров и кнопки добавления мысли. HTML не встроен в приложение. Интерактивность JavaScript используется только как UX-эталон, эвристики и localStorage не переносились.

Сохраняются различия Android/браузера: реальные системные панели, растеризация текста, нативные тени/шторки, увеличенные области нажатия. Внутри доступной области заголовки теперь имеют одинаковую координату. На низких экранах весь список прокручивается, длинная карточка растёт без обрезки. Карточки списка, как в HTML, показывают название одной строкой; полный текст доступен в главной карточке.

Новое приложение, новый экран «Все дела» и новые внешние сервисы не создавались. Навигация из пяти вкладок, палитры, welcome, ввод текста и существующие состояния анализа сохранены. Реальный серверный цикл анализа в текущем проекте ещё не подключён: остаётся честное состояние «Не настроен ИИ», а не фиктивный результат.

Ограничение локального этапа остаётся прежним: ViewModel/SavedStateHandle не заменяют постоянную базу и не гарантируют сохранение данных после force-stop/новой сессии. Физический телефон во время этого обновления не подключён; результаты этого отчёта относятся к эмулятору.

Основание для ленивого списка и стабильных ключей: [официальная документация Compose](https://developer.android.com/develop/ui/compose/lists).
