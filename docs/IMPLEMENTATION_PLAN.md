# План для coding-agent: вертикальными срезами, НЕ одним большим запросом

## Этап 1 — компилируемый Android-проект и визуал
- Создать проект Kotlin + Compose, собрать debug APK.
- Сначала базовые дизайн-токены, тема/палитры/тёмная тема, оболочка с 5 вкладками, splash/welcome.
- Реализовать **все пять экранов на локальных фикстурах**. Важнее верность v14 clean, чем фиктивная «реальная логика».
- Навигация, анимации, шторки, карточки, жесты; screenshots с телефона/эмулятора.
**Выход:** рабочий APK, перечень отличий от HTML и следующий список исправлений.

## Этап 2 — Local-first, необязательный аккаунт и личный ключ (новое задание пользователя)
- A: аудит существующего v15, общей модели и ограничений SavedStateHandle.
- B: welcome с действиями без аккаунта / регистрация / вход.
- C: Room, постоянные UUID/даты/связи/исходники/результаты, миграции без удаления данных, отдельная демонстрация.
- D: Supabase Auth email+password, имя профиля, шифрованная сессия, refresh и выход. В учебном проекте Confirm Email выключен; кнопки восстановления пароля нет.
- E: явное согласие на перенос локальных записей, сохранение оригиналов, изоляция аккаунтов, RLS, версии/удаления/повторы/конфликты, фоновая очередь.
- F: настройки аккаунта/приложения и BYOK Token Harbor с Keystore, сохранением/заменой/удалением и реальной проверкой каталога моделей.
После каждого среза — сборка. Подробности: `STAGE_2_ARCHITECTURE.md`, `STAGE_2_SETUP.md`.
**Выход:** приложение работает без аккаунта, записи переживают перезапуск, настройки безопасны; внешние интеграции не объявляются проверенными без реального тестового проекта/ключа. Интеллектуальный разбор и транскрибация не входят.

## Этап 3 — полный ручной Capture Flow
- Текст -> сохранение оригинала -> вариант «На потом» -> входящие -> ручной список предложений -> изменение -> транзакционное подтверждение.
- Атомарность подтверждения — транзакция Room; синхронизация следует общей архитектуре этапа 2. История оригиналов и ручной перенос в мысли уже имеют постоянное хранение.
- Не делать анализ моделью в этом этапе, но не выдавать фиктивные эвристики за ИИ.
**Выход:** целиком работающий путь без ИИ, без дублей после повтора.

## Этап 4 — AI Token Harbor
- Только по следующему заданию: полный разбор через AiProvider/AiRepository и личный BYOK из Keystore, независимо от аккаунта Supabase.
- Прямой HTTPS к Token Harbor, выбор реальной модели из каталога, явное согласие на отправку текста, ограничение запроса/парсинг/валидация, понятная ошибка и повтор.
- Оригинал сохраняется локально до сети; предложения становятся записями только после явного подтверждения и транзакции Room.
- Отображение предложений в UI, редактирование и подтверждение работают как в этапе 3.
**Выход:** проверка 10–20 смешанных русскоязычных фраз, отсутствие выдуманных дат, нет непроверенных автодействий.

## Этап 5 — распознавание речи и полировка
- SpeechRecognizer с interim/final и отказом разрешения, graceful fallback на текст.
- Экран микрофона и его анимации, loading, responsive widths, offline/error states.
- CRUD идей/дневника/календаря/проектов/ожиданий, недельный обзор, восстановление сессии.
**Выход:** видео/скриншоты 5 экранов на Android, успешный полный сценарий «говорю -> редактирую -> подтверждаю -> вижу».

## Этап 6 — качество перед демонстрацией
- UI/unit tests и RLS тесты, kill/relaunch, offline behavior, больших шрифтов, keyboard/windowInsets.
- Убрать debugging/dev shortcuts и секреты из APK, проверить Privacy & Permissions.
- Подготовить README: установка, переменные окружения, миграции, схема, запуск, известные ограничения.

## Definition of done
Нельзя объявить весь проект готовым, если только выглядят экраны. Точно так же нельзя объявить готовым, если только работает база, а дизайн не похож на v14. Каждый пункт подтверждён конкретной проверкой, screenshot или тестом.
