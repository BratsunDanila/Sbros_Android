# Этап 1 · нативный визуальный прототип

Работа ограничена этапом 1 из `IMPLEMENTATION_PLAN.md`. Этап 2 не начат.

## Реализовано

- Запускаемый Android Studio проект: Kotlin, Compose, Material 3 с собственными поверхностями, Navigation Compose, ViewModel/StateFlow, SavedStateHandle, DataStore для настроек.
- Приветствие, состояние загрузки настроек, начальная вкладка «Сброс».
- Ровно пять нижних пунктов: **Дела | Мысли | Сброс | Календарь | Обзор**. Центральный микрофон 41×36 dp, внутри панели, без выступающей FAB.
- Цветовые токены HTML для lavender/sage/clay/ocean и dark. В тёмной теме все палитры, как в исходном CSS, используют общую тёмную палитру.
- Оригинальный встроенный Onest, включая промежуточные веса 650/750/760, с SIL OFL. Иконки SVG эталона перенесены в VectorDrawable, декорации — Canvas.
- Дела: уровни сложности, стопка, следующий элемент, завершение/отмена, горизонтальные свайпы с отметкой направления и пружинящим возвратом, пустое состояние.
- Мысли: четыре фильтра, поиск по словам, лента, полный текст, избранное, редактор, продолжение, удаление/отмена, явное создание действия с сохранением исходной мысли. «Новая мысль» ведёт в единый ввод «Сброс».
- Календарь: месяцы, выбор дня, маркеры событий, пустой день, локальное добавление/изменение/удаление событий, пустое время означает весь день. Дата и время проверяются.
- Обзор: входящие с полным текстом, плитки/списки фикстур, выполненные дела, недельный чек-лист, пустая история разборов.
- Настройки, светлая/тёмная тема, палитры, сброс фикстур с подтверждением. Смена экранов ~220 ms, анимированный выбор, пружина свайпа и нативные шторки. Compose использует системный масштаб длительности анимаций; постоянной пульсации микрофона нет.

## Сборка и проверка

Среда: JDK 21 из Android Studio, Android SDK на `D:/andriodsdk`, API 35. Для воспроизводимости используется существующий совместимый набор AGP 8.7.3 / Gradle 8.11.1 / Kotlin 2.0.21 / Compose BOM 2024.10.01. Это не последние версии 2026 года; перед публикацией требуется запланированный апгрейд.

Команды из корня:

```powershell
$env:JAVA_HOME='D:/andriodstudio/jbr'
./gradlew.bat assembleDebug assembleDebugAndroidTest lintDebug
./gradlew.bat connectedDebugAndroidTest
```

Debug APK: `app/build/outputs/apk/debug/app-debug.apk`.
Lint: `app/build/reports/lint-results-debug.html`.

Для проверки создан отдельный Android 15 AOSP эмулятор, x86_64, 160 dpi, WHPX, программный GPU. Его данные отделены от существующих пользовательских устройств. Физический телефон не подключён. Визуальные тесты снимают настоящий дисплей Android, а не HTML или Compose Preview.

`VisualSmokeTest` содержит независимые проверки внешнего вида и локального поведения. Проверяются все пять вкладок, тёмная тема и четыре палитры, поиск/открытие мысли, смена месяца, фильтры и завершение дел, пересоздание Activity с черновиком, явное состояние «Не настроен ИИ».

Подтверждённые результаты: debug APK и тестовый APK собраны, Lint — **0 ошибок, 21 предупреждение**. На 360×800 и 390×844 прошли оба UI-теста. На 320×690 с жестовой системной навигацией прошёл визуальный тест всех вкладок/палитр. Протоколы и PNG находятся в `screenshots/<размер>/`; оригинальные изображения в `reference/` не изменены.

Итоговая композиция: `screenshots/native-all-screens.png`. Сопоставление: `screenshots/reference-vs-native.png` — сверху исходный коллаж, снизу снимки Android 390×844. Это монтаж реальных снимков, без дорисовки интерфейса. Приветствие: `screenshots/390x844/00-welcome.png`.

Первоначальный APK `0.1.0-demo` имел SHA-256 `3B2BD51E35ABE0EDDF1FF58E0EBAD8CE57FFF67A41F0E26AB97B1E1DC5E10E0C`. Снимки в каталогах размеров относятся к этой версии. Текущий APK обновлён исправлением шрифта, описанным ниже; его контрольная сумма хранится рядом с APK в `app-debug.apk.sha256`. ## Сравнение с эталоном

Основной источник — полностью прочитанный `reference/sbros_v14_clean.html`, включая финальные переопределения v14 compact headers. Просмотрены `v14_all_screens.png`, отдельные изображения дел/мыслей/тёмного обзора и узкие варианты сброса/календаря. Открытие локального HTML во встроенном браузере заблокировано политикой URL; интерактивный сценарий разобран по исходному JavaScript. Обход блокировки не применялся.

Сохранены композиции заголовков, подписи, мягкие блоки, карточная иерархия, порядок навигации, цветовые значения и размеры центрального микрофона. Нет удалённых верхних технических подписей, псевдостатусбара или рамки телефона.

Оставшиеся визуальные различия:

1. Настоящие Android status/navigation bars занимают место иначе, чем вебовый статусбар. На трёхкнопочной системной навигации видимая область ниже на 48 dp. Дата и время настоящие, а календарь использует дату устройства; эталон содержит 28 октября и 9:41.
2. На 360×800 композиция сброса компактнее большого HTML-варианта, чтобы обе кнопки оставались доступны над системными панелями. На 390×844 сохраняется большая композиция. На низких экранах содержимое можно прокрутить.
3. Onest и веса оригинальные, но растеризация, кернинг и переносы текста Android/Chrome могут отличаться на несколько пикселей. Некоторые touch targets увеличены относительно веба.
4. Canvas воспроизводит геометрию колец и звёзд, но CSS color-mix, blur, псевдоэлементы и тени не совпадают побитно с Android Canvas/elevation. Декоративные кольца статичны; бесконечное дрейфование вебового макета не перенесено.
5. Шторки и поля ввода используют нативную Material 3 механику: ручка, клавиатура, скролл и floating labels отличаются от HTML. Эти отличия особенно видны при редактировании, а не на пяти основных экранах.
6. Части «Обзора», продолжительная лента мыслей и выбранный день календаря на низком экране требуют прокрутки. Нижняя навигация остаётся доступной и не перекрывает область скролла.

Это визуально близкий нативный первый срез, не заявление о попиксельной идентичности. Следующая визуальная правка после пользовательской проверки: подстроить интервалы/переносы на реальном телефоне, при необходимости приблизить формы шторок и тени.

## Границы и технические ограничения

- Нет Supabase, Auth, Token Harbor, SpeechRecognizer, API-ключей и сетевых разрешений. «У меня уже есть аккаунт» честно объясняет границу этапа 2. Микрофон/разбор/помощь не симулируют готовую интеграцию.
- «На потом» работает в локальной демонстрационной сессии. ViewModel и SavedStateHandle переживают конфигурационные изменения и системное восстановление Activity, но не заменяют постоянную базу. После force-stop/новой сессии изменения фикстур могут исчезнуть. Не использовать первый APK для незаменимых личных записей.
- Полного ручного списка предложений и атомарного Capture Flow пока нет: это этап 3. История подтверждённых разборов поэтому пустая. Оригиналы локальных входящих не обрезаются до заголовка.
- Вложенные проекты и материалы показывают фикстуры; полный редактор проектов/задач и постоянный CRUD остаются следующим этапам. Семантический поиск не реализован.
- Основные интерфейсные строки вынесены в Android resources. Тексты локальных примеров и часть подписей вспомогательных шторок пока русские в коде.
- Lint предупреждает о более новых зависимостях и неиспользуемых векторах/ресурсах. Требуется отдельная проверка Android 8, физического телефона, больших системных шрифтов и всех служб системного ввода на следующих этапах.

Миграция SQL прочитана как контекст будущего этапа. Она не применялась и RLS не проверялся; серверная интеграция готовой не объявляется.

## Исправление шрифта · 0.1.1-demo-fontfix

После проверки пользователем обнаружено, что на физическом Xiaomi с Android 16 начертания существенно тоньше эталона. Причина воспроизведена регрессионным тестом через `createFontFamilyResolver` Compose: при использовании одного вариативного TTF запросы 400, 700 и 760 на этом устройстве давали одинаковые контуры. Измеренная сумма покрытия чёрным для одной строки была **1871.55 для каждого из трёх весов**. Эмулятор Android 15 эту несовместимость не выявлял.

Все восемь используемых весов теперь включены отдельными статическими TTF, полученными из того же исходного Onest через fontTools, без изменения дизайна букв. Нужные контуры и `usWeightClass` записаны непосредственно в файлы; runtime-вызовы `FontVariation` удалены. Промежуточные 650/750/760 сохранены, автоматическое округление к стандартным весам не требуется.

Повторный тест на том же физическом устройстве прошёл: 400 → **1871.55**, 700 → **2921.01**, 760 → **3119.25**. То есть жирный и заголовочный веса больше не совпадают с обычным. Протоколы, метрики и реальные растровые образцы до/после: `screenshots/font-fix/`. Проверка касается загрузчика Compose и отрисованных букв; полный UI-прогон на физическом телефоне не завершён и успешным не объявляется.

`assembleDebug`, `assembleDebugAndroidTest`, `lintDebug` выполнены успешно; Lint — 0 ошибок, 21 предупреждение. Исправленный APK установлен на подключённый телефон через обновление, без очистки данных. Авторизация/сервер/ИИ не добавлялись, границы этапа 1 сохранены.

Для воспроизведения статических файлов: `python scripts/Generate-OnestStatic.py` с fonttools 4.62.1. Оригинал сохранён в `tools/fonts/Onest-variable.ttf`, лицензия — `licenses/Onest-OFL.txt`, контрольные суммы — `tools/fonts/instances.json`. Генератор проверяет кириллицу, отсутствие вариативных таблиц и различие контуров.

Официальные источники: [подключение начертаний в Compose](https://developer.android.com/develop/ui/compose/text/fonts), [создание статических экземпляров fontTools](https://fonttools.readthedocs.io/en/latest/varLib/instancer.html).
