# AI-инструкция для сервиса анализа одной исходной записи

> Этап 2 реализует только проверку личного BYOK-подключения, без анализа. Для будущего отдельного задания эти правила классификации сохраняются, а прежние упоминания обязательного сервера нужно адаптировать к local-first/AiRepository: никакой модели нельзя доверять без проверки структуры и явного подтверждения пользователем перед транзакцией Room.

Это **требования к системной инструкции модели**, а не текст, который следует показывать пользователю. Сервер применяет валидацию ответа независимо от модели.

## Задача
На русском языке проанализировать `raw_text` и предложить осмысленные независимые фрагменты. Не все фрагменты — дела. Не заставлять пользователя выполнять задачи. Не выдумывать факты, сроки, контекст или «скрытый смысл».

## Разрешённые `kind`
- `next`: конкретное выполнимое действие. Если фраза слишком широкая, сохранить её максимально близко к оригиналу и/или пометить как `projects`.
- `reflection`: размышление, чувство, описание события без обязательного действия.
- `idea`: идея/замысел, не обязательно обязательство.
- `waiting`: ожидание действия/ответа от другого человека.
- `projects`: желаемый многосоставной результат, не отдельный маленький шаг.
- `cal`: событие с явно заданной датой; нельзя заполнять дату по предположению.
- `someday`: возможное действие «когда-нибудь».
- `notes`: справочный материал, факт или информация на память.
- `inbox`: пользователь неясно сформулировал информацию или её лучше не классифицировать.

## Вход
```
{
  "raw_text": "произвольный текст на русском",
  "today_local": "YYYY-MM-DD",
  "time_zone": "Europe/Bucharest",
  "language": "ru"
}
```
`today_local` и `time_zone` приходят из клиента/сервера и нужны только для явных относительных дат. Не привязывай пользовательский таймзон к примеру выше: приложение получает реальную настройку устройства.

## Выход
Только JSON объекта с полем `proposals`, каждый элемент содержит `kind`, `title`, опциональные `body`, `date` (`YYYY-MM-DD`), `time` (`HH:mm`), `area`, `energy`, `source_excerpt`.
- `kind` только из списка выше.
- `title`: аккуратная формулировка, без добавления неподтверждённых смыслов.
- `date` только для `cal`, при объективно известной дате. Если даты нет — НЕ `cal` или предложи изменить тип.
- `time` только если пользователь реально указал время.
- `energy` необязательно; при неуверенности отсутствует, UI предлагает выбор.
- `source_excerpt`: буквальный короткий фрагмент исходного текста (если указан).
- Сохраняй разнотипные намерения в одной записи отдельно; не дроби целостное размышление на десяток пунктов.
- Не генерируй советы психологического/медицинского характера в классификации. Не оценивай эмоции пользователя.
- Если запись — только дневник, разрешён единственный `reflection`; если нет конкретных действий, никаких выдуманных задач.

## Постобработка сервером
- Валидировать JSON, whitelist `kind`, длину текста, количество элементов, формат дат.
- Удалять/отклонять пустые предложения. Не копировать непроверенные модельные поля напрямую в SQL.
- Возвращать понятную ошибку, если модель дала неправильный формат. Не подменять ошибку демонстрационным результатом.
- Возвращаемые proposals — лишь предложения; запись выполняется только после редактирования и явного подтверждения пользователя.

## Отдельный AI-режим «Маленький первый шаг»
По конкретному делу предложить 1–3 безопасных малых шага, без автоматического изменения списка. Ответ также должен быть валидирован и показан пользователю перед сохранением.
