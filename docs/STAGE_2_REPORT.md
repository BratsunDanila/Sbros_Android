# Этап 2 — local-first, аккаунты и личный ключ ИИ

Версия `0.3.0-local-first`, code 5. Существующий проект и дизайн v15 сохранены; новый Android-проект и WebView не создавались. Новое задание пользователя имеет приоритет над прежним требованием обязательного аккаунта и исключительно серверного ключа Token Harbor.

## Реализовано

- Welcome с основным действием «Начать без аккаунта», регистрацией и входом. Прохождение хранится локально. Авторизация не закрывает доступ к ручным функциям.
- Room — основной источник данных UI в обоих режимах. Постоянные UUID, даты, связи проектов/дел/исходников, ожидания и выполненные действия, мысли/идеи, события, материалы, история сбросов, подтверждённые вручную результаты. Черновик сохраняется отдельно. Схема экспортирована, есть миграция 1→2 без destructive fallback.
- Личные записи начинают пустое пространство. Примеры находятся в отдельном `demo`, обозначены в UI и исключены из синхронизации. Сохранённое состояние предыдущей демоверсии, если Android передал его приложению, переносится в отдельный `legacy`, не превращаясь автоматически в личные записи. Старые данные, уже утраченные прежней версией, восстановить невозможно.
- Редакторы ждут успешной записи, защищены от двойного сохранения и сохраняют текст при ошибке. Устаревшая открытая форма не перезаписывает более новую запись. Удаления — tombstones; отмена проверяет конкретную ревизию и не откатывает последующие правки. Входящие адресуются по UUID, включая одинаковые тексты.
- Supabase Auth через официальный HTTPS API: имя/email/password, регистрация, вход, шифрованная сессия, сериализованный refresh, восстановление кеша офлайн, выход. Пароли не сохраняются. Операция входа принадлежит приложению и переживает пересоздание формы; отмена не оставляет вечное loading-состояние.
- После входа перенос локальных личных записей требует отдельного согласия. Исходные локальные копии остаются, UUID/даты/связи сохраняются, повтор не создаёт дубликатов. «Не сейчас» оставляет записи устройства активными. Кеш каждого аккаунта отделён, выход его не удаляет; UI сразу скрывает пространство, не соответствующее текущему пользователю.
- Облачный протокол с RLS, compare-and-swap версиями, идемпотентными mutation UUID, мягким удалением и страницами. WorkManager ждёт сеть и повторяет задания. Конфликт сохраняет обе копии и требует выбора; после выбора обе версии остаются в локальной истории. API-ключ/токены/черновики не входят в payload.
- Настройки разделены на аккаунт, ИИ и приложение. Тема/палитры сохранены. Есть явное переключение записей устройства/аккаунта, просмотр примеров, безопасный сброс только примеров, информация о хранении.
- Token Harbor BYOK: отдельный AiProvider/AiRepository, ввод, сохранение, замена, удаление, состояния загрузки/ошибки и проверка HTTPS-каталога моделей. Используются реальные ID из ответа, фиксированная модель не выдумывается. Ключ AES-256-GCM — Android Keystore; шифротекст — AtomicFile в noBackupFilesDir. AAD разделяет назначения, IV новый при каждой записи. После сохранения поле очищается; ключ не синхронизируется и не показывается.

## Что требует внешней настройки

Реальные Supabase URL/publishable key отсутствуют в текущей сборке (проверены пустые BuildConfig-поля). Реального пользовательского ключа Token Harbor нет. Поэтому живая регистрация, восстановление настоящей сессии/refresh, перенос в конкретный облачный проект, сетевой цикл двух устройств и проверка реального ключа не объявляются пройденными. Подготовлены рабочие клиенты и инструкции; тесты протокола используют явно обозначенные фикстуры, без замены настоящих запросов симуляцией в приложении.

Локальные SQL-тесты выполняют реальный PostgreSQL/RLS в PGlite 0.5.13 с тестовыми ролями и `auth.uid()`. Они подтверждают SQL-ограничения, но не инфраструктуру Auth/PostgREST реального Supabase. Миграции и межпользовательские сценарии необходимо повторить в тестовом Supabase перед production.

## Ограничения

- Интеллектуальный разбор, подсказки модели и транскрибация не реализованы по границам задания. Проверка каталога не подтверждает средства на счёте или генерацию каждой модели.
- В учебном Supabase подтверждение email выключается, восстановления по email нет. Риски неподтверждённых адресов описаны в инструкции; неработающей кнопки восстановления нет.
- Room хранится в приватной области приложения, полного шифрования БД и локального экспорта пока нет. Удаление приложения удаляет локальные записи; для восстановления нужен успешно синхронизированный аккаунт. Ключ ИИ в облаке не восстанавливается.
- Поле исходного сброса — до 12 000 символов, заголовки — до 500, запись вместе с JSON-полями — до 240 КБ. Превышение размера при сохранении формы отклоняется с сообщением, без обрезки сохранённого оригинала. Пакеты ограничиваются по байтам, большие коллекции загружаются страницами.
- Если запись изменилась во время редактирования, форма сохраняет введённую правку и отказывается перезаписывать новую версию. Для ручного сравнения нужно скопировать правку перед закрытием формы. Конфликты уже сохранённых офлайн-записей имеют отдельный экран выбора и архив обеих версий.
- Фон может задерживаться Android; периодическая проверка — от 15 минут. Force-stop требует повторного открытия приложения. Отметки удаления сохраняются на сервере; политика физической очистки/retention требует отдельного решения.
- Сохраняются системные различия Android: панели, клавиатура, нативные шторки и растеризация. Новые формы выполнены в стиле v15, попиксельное наложение с браузером не выполнялось. Полоса демонстрации видна только в отдельном режиме примеров.

Следующие этапы анализа/транскрибации не начаты.
