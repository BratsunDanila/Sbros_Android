# Этап 2: local-first и личный ключ ИИ

Основание — новое задание пользователя «Сброс — этап 2: Local-first, аккаунты и настройки ИИ». Оно заменяет прежние требования об обязательном аккаунте, серверном источнике данных и только серверном ключе Token Harbor. В этом этапе ИИ и транскрибация не реализуются.

## A. Аудит

В v15 основные экраны и редакторы уже работают. Данные — `DemoState` в ViewModel/SavedStateHandle; постоянны только тема/палитра/onboarding в DataStore. Room, сеть, авторизация и синхронизация отсутствуют. Схема `001_core.sql` подготовлена, но не применялась к реальному Supabase. Векторы и статические начертания Onest сохраняются.

## Решения

- Общий Repository и Room — единственный источник пользовательских записей в обоих режимах. UUID, даты, мягкое удаление, очередь изменений, отдельные пространства устройства/аккаунта/демо. UI-модели совместимы с v15; целочисленные ID используются только для отображения, синхронизация — по UUID.
- Вход не обязателен. Гостевые записи не отправляются в Supabase автоматически. Импорт в аккаунт требует явного согласия, сохраняет UUID/даты/связи и повторяется безопасно. Выход переключает пространство, сохраняя данные аккаунта на устройстве.
- Supabase Auth email/password через официальный HTTP API, без собственного хранения паролей. Access/refresh tokens шифруются Keystore. Публичные URL/key задаются разработчиком, service_role/secret key запрещены.
- Синхронизация использует версионирование и tombstones. Конфликт не решается молчаливой перезаписью: обе версии сохраняются локально и предлагаются пользователю. Исходные сбросы и подтверждённые результаты имеют постоянные связи.
- BYOK: ключ Token Harbor хранится отдельно от Room, только в зашифрованном файле noBackupFilesDir, ключ AES-GCM — Android Keystore. Проверка подключения не отправляет личные записи и не запускает генерацию.
- Экраны v15 сохраняются; новые формы/настройки используют существующий дизайн.

## Последовательность

A аудит → B welcome/гостевой режим → C Room/постоянные записи → D Auth → E согласие/синхронизация/изоляция → F BYOK и настройки. После каждого среза — компиляция. Отсутствующие параметры Supabase/ключ пользователя не заменяются фиктивными значениями.
