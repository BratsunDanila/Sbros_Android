# Сброс · Android · v15 · local-first

Нативное Kotlin + Jetpack Compose приложение с пятью основными вкладками. Текущая версия: **0.4.1-relational** (code 7). Дизайн v15, статические начертания Onest и исходные SVG сохранены. WebView отсутствует.

## Актуальная настройка Supabase

Для перехода с `sync_records` примени `003_relational_domain.sql`, затем `004_remove_weekly_reviews.sql`. Если 003 уже применена, нужна только 004. Затем установи обновлённое приложение через Run app. Пошаговая инструкция: [DATABASE_SETUP.md](docs/DATABASE_SETUP.md). Предметные таблицы, ER-диаграмма и синхронизация v3: [DATABASE_ARCHITECTURE.md](docs/DATABASE_ARCHITECTURE.md).

Код включает голосовой ввод, реальный BYOK-разбор и журнал завершённых попыток ИИ. Историческое описание этапа 2 ниже относится к более раннему состоянию. Сборка и проверки новой реляционной схемы в этой сессии не запускались по просьбе пользователя.

## Запуск

Открой корень в Android Studio, выполни Gradle Sync, выбери устройство и **▶ Run app**. JDK 17/21, SDK Platform 35, minSdk 26. `local.properties.example` содержит пример конфигурации. Для локальной работы никакие ключи не нужны.

```powershell
$env:JAVA_HOME='D:/andriodstudio/jbr'
./gradlew.bat assembleDebug assembleDebugAndroidTest testDebugUnitTest lintDebug --offline --no-daemon --no-watch-fs --console=plain
```

При первом получении зависимостей убери `--offline`. APK: `app/build/outputs/apk/debug/app-debug.apk`.

## Что изменилось на этапе 2

- Основное действие welcome — «Начать без аккаунта». Вход/регистрация необязательны, onboarding сохраняется.
- Room хранит дела, проекты, мысли/идеи, события, ожидания, выполненные дела, оригиналы сбросов, подтверждённые вручную результаты и связи. Черновик, выбор дела и отмена также сохраняются.
- Личные записи начинаются с пустого пространства. «Посмотреть примеры» в настройках открывает отдельную демонстрацию с подписью; её сброс не затрагивает личные записи. Восстановленное состояние прежней демоверсии сохраняется отдельно, если Android передал его при обновлении. Уже утраченные старой версией данные восстановить невозможно.
- «На потом» атомарно сохраняет оригинал и очищает черновик. Во входящих можно явно перенести запись в мысли; исходник и связь остаются в истории. Из мысли можно явно создать действие, сохранив происхождение.
- Supabase Auth использует email/password, имя, шифрованную сессию, refresh и выход. Нужны реальные публичные параметры проекта. В учебном Supabase Confirm Email отключается; восстановления по email пока нет.
- После входа перенос записей устройства предлагается отдельно. При отказе они остаются локальными. Выход сохраняет записи аккаунта в отдельном кеше; другой аккаунт их не видит.
- Синхронизация использует UUID, версии, отметки удаления и WorkManager с сетевым ограничением. Конфликты требуют выбора; обе версии сохраняются. Старый открытый редактор не перезаписывает более новую запись.
- Настройки ИИ принимают личный Token Harbor BYOK. Ключ шифруется через Android Keystore и хранится вне резервных копий. Сохранение/замена/удаление и HTTPS-проверка каталога моделей отделены от аккаунта. Сохранённый ключ не показывается.
- Анализ, подсказки ИИ и распознавание речи ещё не подключены. Сообщения интерфейса не имитируют их работу.

## Документация

- `docs/STAGE_2_SETUP.md` — точная настройка Supabase Dashboard, публичных параметров, миграций, BYOK и тестов.
- `docs/STAGE_2_ARCHITECTURE.md` — архитектурные решения и приоритет нового задания.
- `docs/STAGE_2_REPORT.md` — фактические результаты проверки, APK и ограничения.
- `docs/V15_DETAILS_REPORT.md` — предыдущее исправление вложенных экранов/редакторов и иконок.

Постоянные записи — Room, темы и режим просмотра — DataStore, секреты — зашифрованное Keystore-хранилище. Java-классы в `data/local` — тонкая Room-схема/DAO с обычным annotation processor; Repository, бизнес-операции, сеть и UI реализованы на Kotlin. Схема Room экспортирована в `app/schemas`, destructive migration не используется.

`supabase/migrations/002_local_first_sync.sql` применяется после 001, сохраняет подготовленные записи и переводит облачное хранение на единый протокол. Локальные PostgreSQL/RLS-тесты: `supabase/tests/run-local-sync.mjs`. Они не заменяют живую проверку Supabase Auth/PostgREST.

Исходники макетов — `reference/`. Шрифт Onest включён в APK, лицензия — `licenses/Onest-OFL.txt`. Генераторы статических TTF и иконок сохранены в `scripts/`.

Удаление приложения удаляет локальные записи. Для восстановления после потери устройства нужна успешная явно разрешённая облачная синхронизация. Компоненты ОС могут задерживать фоновую работу. База находится в приватном хранилище приложения; полного шифрования Room и экспорта резервной копии пока нет. Личный ключ ИИ не загружается в Supabase и не входит в APK.
