# СБРОС — пакет передачи проекта ИИ-агенту

## Актуализация: предметная схема Supabase v3
Последующими заданиями пользователь разрешил и получил SpeechRecognizer, полный BYOK-разбор и переход на отдельные облачные таблицы. Действующий SQL: `supabase/migrations/003_relational_domain.sql` после 001/002, затем `004_remove_weekly_reviews.sql`. Недельный обзор удалён: осталась только UI-плашка актуальности с галочкой, без истории и таблицы. Клиент вызывает `sync_push_v3` / `sync_pull_v3`; `sync_records` больше не является хранилищем. Источник настройки: `docs/DATABASE_SETUP.md`, модель и ER-диаграмма: `docs/DATABASE_ARCHITECTURE.md`. Room и необязательный аккаунт сохраняются; ключ ИИ — только Keystore. Пользователь просит не запускать тесты, сборку и скриншоты в текущей работе; эту установку учитывать до её изменения пользователем. Описания ограничения этапа 2 «только проверка подключения» ниже исторические и заменены последующими заданиями.

> Актуализация этапа 2: приложение local-first, аккаунт необязателен, Room — основной источник данных. Supabase используется для явно разрешённой синхронизации; личный Token Harbor BYOK хранится зашифрованным на устройстве. Интеллектуальный разбор/транскрибация требуют следующего задания. Основной макет — v15. Прежние серверные требования этого документа заменены новым заданием пользователя: см. `docs/STAGE_2_ARCHITECTURE.md`, `docs/STAGE_2_SETUP.md`.

## Что это за приложение
**«Сброс» — интеллектуальный помощник для структурирования личных планов и мыслей**. Пользователь может одним голосовым или текстовым вводом выгрузить дела, идеи, переживания и наблюдения. ИИ предлагает разбор на осмысленные элементы, но ничего не фиксирует без явного подтверждения. После подтверждения дела появляются в «Делах», идеи/дневник — в «Мыслях», события с точными датами — в «Календаре», а GTD-структура и история — в «Обзоре».

Тема учебной работы: «Разработка мобильного приложения для интеллектуального структурирования и управления личными планами на основе искусственного интеллекта».

## Технологии
- Kotlin (нативный Android), Jetpack Compose + Material 3 как базовые компоненты с кастомным оформлением.
- Kotlin Coroutines/Flow, ViewModel, Repository, Navigation Compose, DI (Hilt/Koin по согласованному выбору).
- Supabase: Auth, Postgres, Row Level Security, Edge Functions.
- Token Harbor: LLM-шлюз для структурирования. Base URL `https://tokenharbor.ai/v1` — проверить официальные инструкции; ID модели выбрать из актуального каталога и вынести в секреты/конфигурацию на сервере.
- Транскрибация: Android `SpeechRecognizer` (доступная на устройстве служба распознавания, часто от Google), с русской локалью и текстовым fallback. Не считать облачный/офлайн режим гарантированным.

## Рекомендуемый процесс
1. Распакуй пакет в корень нового репозитория.
2. Открой этот репозиторий в инструменте ИИ-агента (Cursor/Claude Code/Codex и пр.).
3. Отправь содержимое `START_PROMPT_FOR_AGENT.txt`.
4. Требуй **поэтапную реализацию с рабочими APK/debug сборками**. Пусть сначала сделает дизайн и навигацию, и только затем реальный ИИ.
5. Сравни каждый экран Android с HTML-референсом. Правь расхождения до следующего этапа.
6. Подключи собственный проект Supabase и серверный Token Harbor через переменные окружения, не через исходный код.

## Что точно не входит в обещания макета
Наличие настоящей «памяти»/семантического поиска, облачного TTS/STT, продвинутого планирования и работающего ИИ в HTML не подтверждается. Это дополнительные функции, которые необходимо проектировать и реализовывать отдельно. В MVP можно оставить поиск по тексту и явную помощь ИИ.
